# 校招作品集使用指南

## 项目定位

这是一个把硕士研究问题工程化的独立开源项目，不是套模板的通用机器学习 Demo。它同时展示污水处理专业理解、实验数据治理、统计验证、Python 工程化和部署能力。

建议项目名称保持为：

> OUR-SND 智能曝气调控开源平台

对应研究题目仍原样保留：

> 基于耗氧速率的污水处理同步硝化反硝化智能调控研究

## 简历项目经历写法

**OUR-SND 智能曝气调控开源平台｜独立开发者｜2026.08–至今**

- 围绕污水处理同步硝化反硝化调控，使用 Python 建立从 Excel/CSV 数据审计、OUR 特征构造、TN/SND 双目标建模到曝气建议的完整流程，并用标准数据契约管理跨日期实验批次。
- 设计按日期整批留出的交叉验证，避免同日重复样本泄漏；实现固定分组 5 折、重复分组 5 折、留一日期及滚动时间验证，并完成实时 OUR 特征消融。
- 针对跨日期冷启动性能有限的问题，设计“同日低/中/高三点校准”模式；实现整日留出、滚动时间验证和可配置 R² 发布闸门，且只允许校准范围内插值。
- 将出水 TN≤15 mg/L、90% 误差裕量、历史支持域和曝气剂量效应整合为 A/B/C 级决策规则，输出可执行的分步曝气量并保留人工复测与回退边界。
- 完成 CLI、Streamlit、Docker、Codespaces 和 GitHub Actions 交付；将网页隔离为“关闭上传的公开合成演示”和“一键本地 CSV 导入”双模式，并用 Python 3.10/3.12 CI 验证界面边界、端到端流程与容器构建。

> 注意：若简历需要填写私有验证指标，应以授权环境的可追溯结果为准；公开仓库不保存真实记录数或成绩，也不要把限定校准成绩写成完全未见日期的冷启动性能。

## 90 秒面试讲解

“我的硕士课题研究基于 OUR 的污水处理 SND 智能调控。这个项目不是只训练一个模型，而是把真实科研流程工程化。首先，我把四类工作簿统一成带来源追踪的数据契约，并对缺失、错标和跨日匹配逐行审计。其次，我发现随机拆分会让同一天的重复样本泄漏，所以把日期作为整体做交叉验证，同时比较最大 OUR 和实时 OUR。再次，模型不会直接给一个看似精确但缺乏依据的最低曝气量，而是结合 90% 误差裕量、历史支持域和剂量效应，输出 A/B/C 级分步建议。最后，我把同一套逻辑做成命令行、网页和 Docker，并用 GitHub Actions 自动验收。这个项目最重要的价值，是把专业机理、数据可信度和软件落地连在了一起。”

## 高频追问

### 为什么不用随机拆分？

同一天的 5 组实验共享进水、温度和运行背景，随机拆分会把高度相似的记录分到两边，得到虚高的泛化成绩。按日期整批留出更接近预测未来工况。

### 为什么通过 R² 门控还要强调限制？

门控成绩来自新日期已有三个实测校准点后的范围内插值，不是完全冷启动。主动说明边界体现科研诚信，也避免部署时误用。

### 为什么一定输出一个曝气量？

现场需要可执行值，但证据不足时不能伪造最优解。因此 C 级会明确输出“维持当前值”，B 级只允许小步试运行，A 级才搜索稳态目标。

### 这个项目如何继续升级？

优先增加独立实测出水 TN、DO/ORP、膜通量与跨膜压差，锁定后续月份作外部测试集，再开发带人工确认和故障回退的实时数据接口。
